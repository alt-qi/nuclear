# Как узнать идею в новом условии

В каждой карточке есть признак задачи и маленький пример. Сначала
сравните ограничения примера с теми, что даны на туре.

## Мало разных значений

Дан длинный массив, но все числа от 0 до 10. Нужно посчитать пары
индексов с суммой `S`. Запишем 11 частот. К значению `x` подходит
`S-x`. Перемножаем частоты при `x < S-x`, чтобы учесть пару один раз.
При `x = S-x` выбираем два индекса из одной группы. Длинный массив
прочитали один раз, дальше работаем только с частотами.

## Круг отличается от линии одним стыком

Люди стоят по кругу, у каждого мешок разных чисел. Каждый отдаёт одно
своё число вправо и получает число слева. Хотим, чтобы в мешках
не было повторов. Если полученное число изначально было в мешке, человек обязан
отдать именно его. Иначе он может отдать любое своё.

Пройдём по линии, начиная с произвольного выбора первого человека.
Теперь нужно проверить только число, которое последний передаёт
первому. Если оно создаёт повтор, протянем его дальше по начальному
участку круга, пока оно есть в мешках. В первом мешке без этого числа
старый выбор снова подходит. Если число есть у всех, его передают все.

## Достаточно пары с нужным свойством

Нужно поставить точку посередине между двумя участниками так, чтобы
остальные не пришли раньше этой пары. Кажется, что надо найти
глобально ближайшую пару. Хватит взять любого участника `A` и найти
ближайшего к нему `B`. Пусть расстояние между ними `d`.
В середине отрезка до обоих `d/2`. Если кто-то оказался бы ближе
к середине, он находился бы ближе `d` к `A`, что противоречит
выбору `B`. Поиск соседа фиксированной точки требует одного прохода.

## Ожидаемая стоимость складывается из вкладов

Задача просит среднюю стоимость случайного процесса. Сначала выпишите
цену обязательных действий. Затем найдите, какой отдельный факт
добавляет единицу к стоимости.

Например, обработка равномерно случайной перестановки стоит `n` действий плюс одно за
каждую инверсию. У каждой пары чисел вероятность быть в обратном
порядке равна `1/2`. Средняя стоимость равна
`n + n(n-1)/4`. Для сложения ожиданий связь между парами не мешает.

## Жадный выбор можно обосновать обменом

Нужно взять как можно больше непересекающихся встреч. Выбираем встречу
с самым ранним концом. Возьмём любой оптимальный набор и заменим в нём
первую встречу нашей. Она заканчивается не позже, поэтому остальные
встречи остаются допустимыми. Теперь можно повторить тот же аргумент
для оставшегося времени.

## Будущему нужна только часть истории

Из ряда чисел нужно выбрать набор с максимальной суммой, причём
три выбранных числа подряд запрещены. При движении слева направо
будущим решениям важно только, сколько последних чисел мы взяли
подряд. Храним три значения DP для длин 0, 1 и 2. Пропуск сбрасывает
длину в ноль, выбор увеличивает её на один. Из состояния 2 выбирать
следующее число уже нельзя.

## Проверка всего отрезка сводится к краям диапазона

Есть обновления массива и запрос «лежат ли все числа этого отрезка
в диапазоне `[L,R])?». Хватит минимума и максимума отрезка.
Если минимум хотя бы `L`, а максимум строго меньше `R`, все элементы
подходят. Пара из минимума и максимума сливается из двух половин,
поэтому её удобно хранить в дереве отрезков.

## Считать вклад элемента

Нужно сложить суммы всех подотрезков. Вместо перебора отрезков
посмотрим на элемент в позиции `i`. Слева у него `i+1` возможных
начал, справа `n-i` возможных концов. Он войдёт в ответ
`(i+1)(n-i)` раз. Складываем `a[i]·(i+1)(n-i)` за один проход.

## Вычесть плохие варианты без повторов

Нужно число подотрезков хотя бы с одним нулём. Всего есть
`n(n+1)/2` подотрезков. Плохие целиком лежат в непрерывных блоках
между нулями. Блок длины `k` даёт `k(k+1)/2` плохих вариантов.
Каждый плохой отрезок лежит ровно в одном блоке, поэтому можно
просто вычесть сумму по блокам.

## События одной группы читать из старого слоя

Можно пользоваться переходами только со строго возрастающим временем.
Если рёбра `1→2` и `2→3` имеют время 5, по ним нельзя пройти подряд.
При немедленном обновлении DP второе ребро увидит результат первого
и ошибочно разрешит путь. Все переходы времени 5 считаем по старым
значениям, затем применяем их одновременно.

## Хранить общий сдвиг отдельно

Все точки часто двигаются на одинаковое расстояние, а иногда надо
узнать их положение. Храним исходную координату и общий `shift`.
Сдвиг на 7 означает только `shift += 7`. Если теперь надо найти
точки с реальной координатой хотя бы 15, ищем в сохранённых
координатах начиная с `15-shift`.

## Идти справа налево, если спрашивают о будущем

Для каждого элемента надо найти следующее вхождение того же числа.
Идём справа налево. В словаре хранится ближайшая встреченная позиция
каждого значения. Сначала читаем её как ответ, потом записываем
текущую. Для `[2,1,2,2]` у первой двойки ответ — третья позиция,
у третьей — четвёртая. Поиск по оставшемуся хвосту не нужен.

## Раскрыть максимум до выбора структуры

В переходе DP встречается `max_j(dp[j]+max(a[j],x))`. У каждого
`j` можно взять либо `dp[j]+a[j]`, либо `dp[j]+x`. Значит,
ответ — максимум из `max_j(dp[j]+a[j])` и `x+max_j(dp[j])`.
Если допустимые `j` добавляются по одному, поддерживаем два числа.

## Искать среди остатков вместо целых чисел

Нужно найти наименьшее положительное число из цифр 0 и 1, кратное
`m`. Строим его слева направо. Для продолжения важен только остаток
`r`. После добавления цифры `d` новый остаток равен
`(10r+d) mod m`. Запускаем BFS от числа 1, переходы пробуем в порядке
0, затем 1. Когда получим остаток 0, восстанавливаем цифры по предкам.
У графа всего `m` состояний, даже если само число очень длинное.

## Сначала доказать границу, затем построить ответ

Нужно как можно меньше рёбер в связном простом графе, где одно ребро входит
в два простых цикла. При `n-1` рёбрах граф — дерево, при `n`
есть только один цикл. Значит, нужно хотя бы `n+1`.
Для `n≥4` строим два треугольника с общим ребром, затем подвешиваем
оставшиеся вершины листьями. Получается ровно `n+1` рёбер.

## Перебрать маленькую часть полностью

После основной конструкции осталось решить, какие из пяти объектов
взять. Можно попробовать все 32 подмножества и выбрать подходящее.
Надо доказать, что осталось не больше пяти объектов и что проверка
подмножества учитывает все ограничения. Тогда малый перебор становится
частью общего алгоритма.
