# Теория перед туром

Начинайте с вопроса из карточки. Если он похож на условие задачи, проверьте,
какие данные нужны методу и какие ограничения он использует.

## T01. КТО, расширенный НОД и остатки суммы цифр

**Как найти целое число, когда известны его остатки?**

Расширенный Евклид возвращает НОД и два коэффициента. Например,
`extended_gcd(30,18)` даёт `g=6, x=-1, y=2`, потому что
`30·(-1)+18·2=6`. Если нужно получить справа 12, умножаем оба коэффициента
на 2. Получить 7 невозможно, поскольку каждое слагаемое делится на 6.

В общем случае при `g=gcd(a,b)>0` уравнение `ax+by=c` решается, если
`c` делится на `g`. Из одного решения `(x0,y0)` получаем все остальные,
прибавляя к нему `t·(b/g, -a/g)` для целого `t`. Если `a=b=0`,
достаточно проверить `c=0`.

**Объединение остатков.** Пусть число даёт остаток 3 при делении на 4
и остаток 5 при делении на 6. Все кандидаты из первого условия имеют вид
`x=3+4t`. Подстановка во второе условие даёт `4t ≡ 2 (mod 6)`.
Делим всё на 2 и получаем `2t ≡ 1 (mod 3)`, откуда `t ≡ 2 (mod 3)`.
Значит, ответы — `11,23,35,…`, то есть `x ≡ 11 (mod 12)`.

Для остатков `a,b` и положительных модулей `m,n` получаем
`mt ≡ b-a (mod n)`. Если `b-a` не делится на `g=gcd(m,n)`, ответа нет.
Иначе делим сравнение на `g`. Коэффициент `m/g` теперь обратим по модулю
`n/g`, и расширенный Евклид даёт его обратный. Итоговый модуль равен
`lcm(m,n)`.

`crt_merge(3,4,5,6)` возвращает остаток 11 и модуль 12. Для нескольких
условий начинаем с остатка 0 по модулю 1 и объединяем по одному. Проверяем
статус после каждого шага. Несовместность остатков и слишком большой НОК
имеют разные статусы. Успешный остаток лежит в `[0,modulus)`.

В основании `b` число сравнимо с суммой цифр по модулю `b-1`.
Все степени `b` дают остаток 1. Если задача выдаёт суммы цифр в разных
основаниях, из них можно собрать условия для КТО.

## T02. НОД как инвариант достижимости

**Можно ли попасть в заданное состояние шагами фиксированной длины?**

При шагах `+w` и `-r` остаток по `g=gcd(w,r)` сохраняется.
Из нуля можно попасть только в кратные `g`. Чтобы доказать достижимость,
нужно также учесть, какие промежуточные состояния разрешены.

Пусть буфер ёмкости `L` изначально пуст. Запись добавляет `w` байт,
чтение забирает `r`. При `L-w<x<r` нельзя сделать ни то ни другое.
Тупик достижим ровно при `L<r+w-g`.

Если `L≥r+w-g`, в интервале тупика нет кратных `g`. Для обратного
направления читаем при `x≥r`, иначе записываем. Без проверки ёмкости это
прибавление `w` по модулю `r+w`. Такой цикл из нуля посещает все
кратные `g` до `r+w-g`. Если ёмкость меньше максимума, прямо перед
первым выходом за неё чтение невозможно, а запись не помещается.

## T03. Линейная алгебра над GF(2) и XOR-базис

**Даны числа. Можно ли выбрать несколько из них и получить заданный XOR?**

XOR складывает биты без переносов. `1 xor 1 = 0`, `1 xor 0 = 1`.
Одно и то же число, взятое дважды, исчезает из XOR. Например,
`5 xor 3 = 6`, потому что `101 xor 011 = 110`.

Пусть даны `5,3,6`. Из `5` и `3` уже можно получить `6`.
Значит, отдельное число `6` ничего не добавляет. Возможные результаты —
`0,3,5,6`. XOR-базис хранит числа, из которых получаются все эти
результаты. У сохранённых чисел разные старшие единичные биты.

Как вставить число:

1. Берём его старший единичный бит. Если в этом разряде уже есть число
   базиса, делаем XOR с ним. Старший бит исчезает.
2. Повторяем с тем, что осталось. Если нужная ячейка свободна, записываем
   остаток в неё. Если дошли до нуля, число уже выражается через базис.

Для `6 = 110` сначала используем `5 = 101`. Получаем `011`, то есть
`3`. Затем XOR с `3` даёт ноль. Чтобы проверить запрос, делаем то же
самое без вставок. Для `4 = 100` после XOR с `5` останется `001`.
Числа со старшим битом в этом разряде нет, поэтому 4 получить нельзя.

Проверка и вставка стоят `O(B)` для `B` битов. У базиса из `r` чисел
`2^r` разных результатов. Любые две разные комбинации различаются в
старшем разряде, где они по-разному выбрали число базиса. Для максимума
идём по битам сверху вниз и применяем XOR, если он увеличивает ответ.

**Зачем это в графе.** Построим остов неориентированной компоненты и
запишем `d[v]`, XOR пути от корня до вершины. Неостовное ребро
`(u,v,w)` замыкает цикл со значением `d[u] xor d[v] xor w`.
Путь по остову из `s` в `t` даёт `d[s] xor d[t]`. Если разрешено
проходить вершины и рёбра повторно, можно добавить к нему XOR любого
набора циклов. До нужного цикла идём и возвращаемся тем же путём, поэтому
эти дополнительные рёбра сокращаются. Для условия о простом пути это
рассуждение неприменимо.

**Что означает GF(2).** Все значения равны 0 или 1, сложение — XOR.
Если есть уравнения вроде `x xor y = 1`, их можно складывать друг с
другом, убирая одинаковые переменные. Это Гаусс над GF(2). Строка
`0 = 1` означает противоречие. Если осталось `f` свободных переменных,
решений `2^f`.

## T04. DSU с потенциалами, small-to-large и параллельный бинарный поиск

**Добавляем рёбра. Как быстро узнать, соединены ли две вершины?**

DSU, или СНМ, хранит для каждой группы представителя. Сначала все вершины
отдельно. `unite(0,1)`, затем `unite(1,2)` дают одну группу из трёх
вершин. Теперь `same(0,2)` вернёт true, а `size(1)` вернёт 3.

`find(v)` поднимается по родителям до корня и переподвешивает посещённые
вершины прямо к корню. При объединении меньшую группу подвешиваем к большей.
Вместе это даёт практически постоянное амортизированное время на операцию. Если корни уже
одинаковые, `unite` возвращает false. Так можно пропускать рёбра,
которые замкнули бы цикл при построении остова.

Для **DSU с XOR-потенциалами** у вершины дополнительно хранится XOR до
родителя. При сжатии пути его нужно заменить на XOR до нового родителя.
Если ребро `(u,v,w)` соединяет разные корни, XOR между корнями равен
`pot[u] xor pot[v] xor w`, где `pot` измеряется до корня. При одинаковых
корнях это значение нового цикла, которое можно добавить в базис из Т03.

Если к группам приписаны списки, переносим меньший список в больший.
Размер группы каждого перенесённого элемента хотя бы удваивается.
Поэтому элемент переезжает не больше `O(log n)` раз.

Для многих запросов о минимальном пороге можно проверять их бинарные
поиски вместе. Например, если разрешать рёбра с весом до `W`, связность
при росте `W` сохраняется. В одном раунде сортируем середины запросов
и добавляем рёбра по возрастанию веса. Все рёбра веса `W` добавляем до
ответа на запрос с этим порогом.

## T05. Граф состояний, SCC, DAG и потенциалы

**Даны зависимости. В каком порядке их обработать и есть ли цикл?**

Пока DFS обрабатывает вершину, она лежит в стеке. Ребро в вершину,
которая всё ещё в стеке, замыкает цикл. Если циклов нет, топологический
порядок ставит начало каждого ребра раньше его конца. Когда `v`
зависит от `u`, это позволяет посчитать `u` до `v`.

В компоненте сильной связности (SCC) из каждой вершины можно дойти
в каждую другую по направлению рёбер. Если заменить каждую SCC одной
вершиной, получится ациклический граф. SCC находятся за `O(V+E)`.

Для равенств `x[v]-x[u]=w` можно выбрать одну величину равной нулю
и восстановить остальные обходом. Например, из `B-A=2` и `C-B=3`
следует `C-A=5`. Если ещё дано `C-A=4`, обнаружится противоречие.

## T06. Кратчайшие пути и сжатие плотных переходов

**Как представить переходы и какой алгоритм выбрать по их ценам?**

Единичные цены — BFS. Только 0 и 1 — 0–1 BFS. Неотрицательные цены —
Дейкстра. Если граф ациклический, достаточно DP в топологическом порядке,
в том числе для отрицательных цен.

Для пути можно хранить пару `(пересадки, время)`. Сравниваем сначала
пересадки, при равенстве время. Дейкстра работает с таким порядком
для неотрицательных прибавок.

Если из любого терминала аэропорта можно доехать в любой другой за одну
пересадку, добавим узел «автобус». Из каждого терминала вход в автобус
стоит одну пересадку, а из автобуса выход в любой терминал бесплатен.
Вместо `k²` переходов храним `2k` дуг. Узел можно использовать,
когда все получившиеся пары переходов действительно разрешены.

## T07. Паросочетания, теорема Холла и отсечение кандидатов

**Каждому участнику нужен свой предмет из списка допустимых. Можно ли раздать?**

Строим граф из участников и предметов. Ребро означает, что предмет
подходит участнику. Паросочетание выбирает рёбра без общих концов.
Например, если трём людям подходят только два предмета, раздать всем
невозможно. По теореме Холла это единственная форма препятствия.
У любой группы из `k` участников должно быть не меньше `k` доступных
ей предметов вместе.

Если есть цены, можно искать распределение потоком минимальной
стоимости. При цене, зависящей только от предмета, для `n` участников
хватит до `n` самых дешёвых вариантов на каждого. Даже если участник
получил отброшенный дорогой предмет, среди оставленных `n` найдётся
свободный. Другие участники занимают не больше `n-1` предметов.

## T08. Потоки, ограничения по группам и разрезы

**Как распределить заявки, когда у каждого пути есть несколько лимитов?**

Ребро с ёмкостью 5 пропускает не больше пяти единиц. В промежуточной
вершине сколько вошло, столько и выходит. Чтобы ограничить саму вершину,
разделяем её на вход и выход и ставим ёмкость между ними.

Например, склад принимает до 10 заказов, из них автомобильных до 3.
Автомобильные сначала идут через дугу с ёмкостью 3. После неё они
попадают в общий узел склада вместе с остальными. Из общего узла выходит
одна дуга с ёмкостью 10. Так соблюдаются оба лимита.

Максимальный поток равен ёмкости минимального разреза. После поиска
потока вершины, куда ещё можно добраться от источника по остаточным
дугам, образуют его сторону разреза. При минимизации стоимости обратная
дуга имеет противоположную цену. Если внутри алгоритма используется
Дейкстра, потенциалы должны делать приведённые цены
`cost(u,v)+pot[u]-pot[v]` неотрицательными на доступных дугах.

## T09. Деревья: Euler tour, HLD, расстояния и центроиды

**Нужны запросы на поддереве, пути или по расстоянию?**

При DFS пронумеруем вершины на входе. Обход полностью заканчивает
поддерево перед переходом в соседнюю ветку, поэтому поддерево — отрезок
`[tin[v],tout[v])`. Теперь прибавление ко всему поддереву становится
прибавлением на отрезке массива.

LCA — ближайший общий предок двух вершин. Путь между вершинами идёт
через него. Поэтому расстояние равно `depth[u]+depth[v]-2·depth[lca]`.
Для взвешенного дерева берём суммы весов от корня вместо глубин.

HLD выбирает у каждой вершины самого большого ребёнка по размеру
поддерева. Остальные переходы уменьшают размер хотя бы вдвое.
Поэтому путь разбивается на `O(log n)` отрезков тяжёлых цепей,
которые можно запросить деревом отрезков.

Центр минимизирует наибольшее расстояние до других вершин. Центроид
делит дерево на куски размера не больше половины. При рекурсивном
разбиении по центроидам у вершины `O(log n)` предков. Для запросов
по расстоянию храним счётчики относительно каждого центроида и вычитаем
вклад ветви запроса, чтобы избежать двойного учёта.

## T10. Дерево отрезков как моноид; ленивые операции

**Что хранить на отрезке, чтобы собрать ответ из двух половин?**

Для суммы достаточно числа. Для чередующейся суммы нужны ещё знаки.
Если левая часть нечётной длины, правая начинается с минуса.
Храним `(s,p)`, где `s` — чередующаяся сумма, `p` — чётность длины.
Тогда слияние `(s,p)` и `(t,q)` даёт
`(s + (-1)^p·t, p xor q)`. Пустой отрезок даёт `(0,0)`.
При фильтрации считаем чётность количества оставшихся элементов.

Ленивая операция должна уметь обновить итог целого отрезка.
Например, `x→ax+b` меняет сумму на `a·sum+b·len`.
Если сначала применили `(a1,b1)`, затем `(a2,b2)`, общий тег равен
`(a2a1,a2b1+b2)`. Порядок важен. Для умножения значений и запросов
суммы нужен соответствующий тег и агрегат.

Если элемент действительно растёт хотя бы вдвое и никогда не превышает
`A`, его можно явно обработать `O(log A)` раз до следующего
присваивания. Умножение на 1 можно пропустить.

## T11. Неявный treap и амортизация уменьшением вдвое

**Нужно вставлять, вырезать или разворачивать куски последовательности?**

У treap по позиции номер элемента вычисляется из размера левого
поддерева. `split(t,k)` отделяет первые `k` элементов, `merge(a,b)`
склеивает две последовательности. Чтобы вырезать `[l,r)`, сначала
разрезаем по `l`, затем правый кусок по `r-l`. При случайных
приоритетах операции занимают ожидаемые `O(log n)`.

Разворот меняет детей местами и ставит флаг. При спуске передаём его детям,
а после изменения детей пересчитываем размер и агрегат. Если агрегат
зависит от порядка, храним итог в обеих ориентациях.

Если каждая дорогая пересборка оставляет не больше половины целого
невосполняемого запаса `H`, пересборок будет `O(log(H+1))`.

## T12. DP с малой памятью и восстановлением ответа

**Ответ надо вывести целиком, а таблица DP не помещается?**

Храним только нужные слои DP. Отдельно для каждого состояния можем
записать, откуда пришли. Например, в клетку можно войти сверху или
слева. Достаточно сохранить направление и потом пройти назад от финиша.
Для трёх типов переходов хватает двух бит на состояние, если по типу
можно однозначно вычислить предка.

Другой способ — посчитать стоимость до середины с обоих концов, выбрать
точку встречи оптимального пути и повторить для двух половин. Это
снижает память. Время нужно оценить по сумме размеров всех подзадач.

## T13. Вероятность: индикаторы, первый шаг и самопереходы

**Нужно среднее число событий или среднее время до результата?**

Если требуется среднее число совпадений, каждому совпадению сопоставляем
0 или 1. Его ожидание — вероятность совпадения. Складываем эти
вероятности. Линейность ожидания работает и для зависимых событий.

Если один шаг стоит одну единицу времени, пишем
`E[s]=1+Σ P(s→t)·E[t]`. Например, бросаем кубик до шестёрки.
На неудаче всё начинается заново, поэтому `E=1+(5/6)E` и `E=6`.
В общем случае самопереход с вероятностью `q` переносим влево и
делим на `1-q`. Когда состояния зависят друг от друга по циклу,
нужны совместные уравнения.

Для случайного удаления из очереди можно идти назад. Если перед
удалением в момент `t` есть `k` заявок, одна выбранная заявка
уйдёт сейчас с вероятностью `1/k`. Поэтому её ожидаемый момент
ухода обновляется как `F ← t/k+(k-1)F/k`.

По модулю дробь `a/b` считаем как `a·b^(-1)`, если `b` обратимо.
Для усреднений по двум равновероятным исходам глубины до `D`
можно хранить числитель в масштабе `2^D`.

## T14. Факториалы, мультиномиальные коэффициенты и циклы перестановки

**Сколько разных порядков, если часть элементов одинаковые?**

Для `L` элементов с частотами `c[i]` ответ `L! / ∏c[i]!`.
Для цифр `0,1,1` это три порядка. Чтобы убрать ведущий ноль,
фиксируем один ноль первым и вычитаем число порядков оставшихся цифр.
Здесь остаются `101` и `110`. Для вычислений через `fact` и
`invfact` по простому модулю `p` нужно `L<p`.

Если считаем перестановки по циклам, новый элемент либо образует новый
цикл, либо вставляется после одного из старых `k` элементов.
Поэтому `c(k+1,j)=c(k,j-1)+k·c(k,j)`, где `j` — число циклов.
Эти числа также получаются как коэффициенты `x(x+1)…(x+k-1)`.

## T15. Свёртка целых чисел через FFT

**Нужно сразу узнать, сколько пар дают каждую возможную сумму?**

Пусть `a[i]` — число предметов веса `i` в первой группе, а `b[j]` —
во второй. Для суммы `k` подходят пары весов `i+j=k`. Каждая такая
пара весов даёт `a[i]·b[j]` вариантов. Сложим их и получим `c[k]`.
Массив всех этих ответов называется **свёрткой**.

Например, `a=[2,1]` и `b=[3,4]`. Сумму 0 дают только веса 0 и 0,
получается 6 пар. Сумму 1 дают веса 0 и 1 либо 1 и 0, получается
`2·4+1·3=11`. Для суммы 2 получаем 4 пары. Итого `[6,11,4]`.

Ту же операцию видно в `(2+x)(3+4x)=6+11x+4x²`. Степени складываются
как веса. Значит, свёртку можно получить умножением многочленов.

**Что ускоряет FFT.** Вместо попарного умножения коэффициентов
вычисляем значения обоих многочленов в одинаковых точках. В каждой
точке значение произведения — просто произведение двух чисел.
Затем обратная FFT восстанавливает коэффициенты. Специальный выбор
точек на единичной окружности позволяет делить задачу на чётные и
нечётные степени и выполнять преобразование за `O(N log N)`.

`convolution_fft(a,b)` делает оба преобразования и округление.
На вход подаются два `vector<long long>`, на выходе коэффициенты.
Пустой вход даёт пустой результат. Длину FFT округляем вверх до степени
двойки, не меньшей `a.size()+b.size()-1`. Иначе старшие коэффициенты
наложатся на младшие. Чтобы посчитать разности, разворачиваем второй
массив. Разность `d` окажется по индексу `d+b.size()-1`.

Заготовка считает в `long double` и округляет вещественную часть.
Она принимает `N≤2^20` и произведение норм входов до `10^12`.
Норма массива — корень из суммы квадратов. При выходе за эти пределы
функция сообщает об ошибке. Для больших точных коэффициентов можно
использовать свёртки по нескольким простым модулям и восстановление КТО.

## T16. Неравенства, транспорт на прямой и допустимые суммы

**Как распределить общий ресурс или перенести предметы между соседями?**

Если на рёбрах пути надо распределить время `T`, а штраф равен
`Σ c[i]·l[i]/t[i]`, то неравенство Коши–Буняковского даёт минимум
`(Σ sqrt(c[i]·l[i]))²/T`. Время на ребре должно быть пропорционально
`sqrt(c[i]·l[i])`. Значит, путь можно искать с такими весами рёбер.

Пусть в двух массивах одинаковое общее число предметов. При соседних
переносах через границу после `i` необходимо перенести её дисбаланс
`|A[i]-B[i]|`, где `A,B` — префиксные суммы. Этого количества достаточно.
Складываем стоимости границ. Если нужен общий ответ для нескольких
распределений, берём медиану префиксных сумм в каждой позиции.
Эти медианы не убывают, поэтому разности соседних префиксов допустимы.

Если соседние целые значения отличаются максимум на 1 и значения
неотрицательны, фиксированная точка `t[a]=A` даёт в позиции `i`
границы `max(0,A-|i-a|) ≤ t[i] ≤ A+|i-a|`. Для двух фиксированных
точек пересекаем их ограничения. Суммы минимального и максимального
профилей можно посчитать по арифметическим прогрессиям.

## T17. Строки: границы, подстроки и палиндромы

**Нужно найти вхождения или понять, где совпадают куски строки?**

У строки `ababa` собственные границы — `a` и `aba`. Это куски,
которые одновременно стоят в начале и в конце. Префикс-функция хранит
длину наибольшей собственной границы каждого префикса. Из длины `j`
переходим к следующей меньшей через `pi[j-1]`. На этих переходах
строится KMP. Z-функция отвечает на другой вопрос. Сколько букв с
позиции `i` совпадают с началом строки?

Переходы `j→pi[j-1]` образуют дерево. Длины префиксов образца, совпадающих
с концом прочитанного текста, лежат на пути от состояния KMP к корню.
Если пронумеровать дерево обходом, проверка предка становится
проверкой попадания в отрезок.

Для числа различных подстрок суффиксный автомат даёт сумму
`len[v]-len[link[v]]` по состояниям кроме корня. Суффиксный массив
даёт `n(n+1)/2-ΣLCP`. Общий префикс двух суффиксов — минимум LCP
между их рангами.

Манакер считает радиусы палиндромов около всех центров за `O(n)`.
В бинарном чётном антипалиндроме симметричные биты различны.
Если инвертировать биты на нечётных позициях, они станут равны.
Дальше можно применить обычного Манакера для чётных палиндромов.

## T18. Геометрия: ориентация, отражения, оболочки и сечения

**По какую сторону от прямой лежит точка и где экстремум?**

Знак `cross(b-a,c-a)` показывает, куда повернули из `a→b` в `a→c`.
Положительный знак — влево, отрицательный — вправо, ноль — точки на одной
прямой. Для отражения точки `p` сначала находим её проекцию `h`
на прямую, затем берём `2h-p`. Для прямой через `a` с направлением
`d` проекция равна `a+d·dot(p-a,d)/dot(d,d)`.

Чтобы найти максимум проекции точек на направление `d`, достаточно
выпуклой оболочки. Линейная функция внутри оболочки принимает значение
между значениями на её вершинах.

Площадь можно считать по вертикальным сечениям. Если суммарная площадь
треугольников меньше площади прямоугольника, найдётся вертикаль, где
сумма длин сечений меньше его высоты. На этой вертикали точно останется
непокрытая точка. Для треугольника длина сечения между соседними
абсциссами вершин меняется линейно.

## T20. Конечные игры и малые грамматики

**Можно ли описать все положения или все допустимые слова?**

Если ходов больше нет, текущий игрок проиграл. Положение выигрышно,
когда можно передать сопернику проигрышное. Например, если за ход
можно взять одну или две монеты, 1 и 2 монеты — выигрышные состояния.
При трёх монетах оба хода дают сопернику выигрышное состояние, поэтому
3 — проигрышное. Так считаем от меньших состояний к большим.

Если допустимых слов мало, можно сгенерировать весь словарь.
Канонических римских записей от 1 до 3999 всего 3999. Для разбиения
строки проверяем, какое слово заканчивается в текущей позиции,
и переходим из DP по префиксу перед этим словом.

## T21. Интерактив: информация, устойчивые сравнения и бюджет

**Сколько ответов может дать запрос и хватает ли лимита?**

Чтобы различить восемь возможных чисел вопросами с ответом «да» или
«нет», нужно хотя бы три вопроса. После двух вопросов есть только
четыре возможных последовательности ответов. В общем случае при
`M` кандидатах и `q≥2` ответах граница — `ceil(log_q M)`.
Она может не достигаться, если разрешённые вопросы плохо делят кандидатов.

Перед реализацией выясняем, ограничено число запросов или их общий
размер. Проверяем равенства и какой ответ означает остановку.
Каждый запрос заканчиваем переводом строки и `flush`.

## T24. Арифметические функции, факторизация и массовая обработка

**Как посчитать делители после разложения на простые?**

У `12=2²·3` есть три варианта степени двойки и два варианта степени
тройки. Значит, делителей шесть, а их сумма
`(1+2+4)(1+3)=28`. Для `n=∏p[i]^alpha[i]` действуем так же.
Количество — произведение `alpha[i]+1`, сумма — произведение сумм
степеней каждого простого.

В `n!` степень простого `p` равна
`floor(n/p)+floor(n/p²)+…`. Сначала считаем кратные `p`, потом
добавляем вторые множители из кратных `p²` и так далее.
Для двойного факториала `(2t)!!=2^t·t!`.

При переборе делителей парами `d,n/d` квадратный корень считаем один раз.
Чтобы посчитать пары с суммой, делящейся на `d`, группируем числа по
остаткам. К остатку `r` подходит `-r mod d`. Если остаток совпадает
со своим партнёром, выбираем два разных элемента из одной группы.
Miller–Rabin отвечает на вопрос о простоте. Для получения простых
множителей нужен алгоритм факторизации.
