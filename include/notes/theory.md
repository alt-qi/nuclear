# Теория перед туром

## T01. КТО и расширенный Евклид

**Как найти число, если известны его остатки?**

`extended_gcd(a,b)` даёт `g, x, y`, где `a·x+b·y=g=gcd(a,b)`.
Например, `30·(-1)+18·2=6`. Чтобы решить `30x+18y=12`, умножаем оба
коэффициента на 2. При `g>0` решение существует, если `g` делит правую
часть. Все решения отличаются на `t·(b/g,-a/g)` при целых `t`.

Пусть `x ≡ 3 (mod 4)` и `x ≡ 5 (mod 6)`. Пишем `x=3+4t`.
Тогда `4t ≡ 2 (mod 6)`, то есть `2t ≡ 1 (mod 3)`. Отсюда
`t ≡ 2 (mod 3)` и `x ≡ 11 (mod 12)`.

В общем случае `x ≡ a (mod m)` и `x ≡ b (mod n)` совместимы, если
`gcd(m,n)` делит `b-a`. Итоговый модуль равен `lcm(m,n)`.
`crt_merge(3,4,5,6)` возвращает остаток 11 и модуль 12. Для нескольких
условий начинаем с `(0,1)` и объединяем по одному, проверяя статус.

## T02. НОД как инвариант

При шагах `+6` и `-4` чётность сохраняется, потому что оба шага
кратны `gcd(6,4)=2`. Из нуля нечётное число получить невозможно.
В общем случае сохраняется остаток по НОД всех шагов. Если остатки
совпали, отдельно проверьте ограничения на промежуточные состояния.

## T03. XOR-базис

Из `5 = 101` и `3 = 011` можно получить `6 = 110` через XOR.
Поэтому из чисел `5,3,6` достаточно хранить `5,3`. Из них получаются
все четыре результата `0,3,5,6`.

Храним по одному числу на каждый возможный старший единичный бит.
Чтобы вставить число, убираем его старший бит через XOR с числом из
этой ячейки. Повторяем с остатком. Если ячейка свободна, кладём туда
остаток. Если пришли к нулю, новое число уже выражается через базис.

Проверяем запрос теми же шагами без вставки. Для `6` получаем
`6 xor 5 = 3`, затем `3 xor 3 = 0`. Для `4` получаем `4 xor 5 = 1`.
Убрать последнюю единицу нечем, поэтому 4 получить нельзя.
Вставка и проверка занимают `O(B)` для `B` битов.

## T04. DSU, или система непересекающихся множеств

**Добавляются рёбра. Как проверить, соединены ли две вершины?**

Изначально у каждой вершины своя группа. `find(v)` возвращает
представителя. `unite(a,b)` объединяет группы, если их представители
разные. Например, после `unite(0,1)` и `unite(1,2)` вершины 0 и 2
в одной группе размера 3. Сжатие путей и объединение по размеру
дают почти постоянное время на операцию. В Краскале берём ребро,
если его концы в разных группах.

## T05. Какой алгоритм выбрать для графа

- Все рёбра стоят 1 — BFS. Стоимости 0 и 1 — 0–1 BFS. Любые
  неотрицательные стоимости — Дейкстра.
- Если ребро `u→v` означает «сначала обработать `u`», нужен
  топологический порядок. Он существует в ориентированном графе без циклов.
- В компоненте сильной связности из каждой вершины можно дойти
  до любой другой. После сжатия таких компонент получится граф без циклов.

## T07. Паросочетание

**Каждому человеку нужен один предмет из списка подходящих.**

Строим двудольный граф. Слева люди, справа предметы, ребро означает
«этот предмет подходит». Кун ищет наибольшее число назначений без
повторов. Чтобы раздать предметы всем, у любой группы из `k` людей
должно быть хотя бы `k` разных подходящих предметов в объединении
их списков. Это критерий Холла. Если назначение имеет цену или один
ресурс можно дать нескольким людям, удобно построить поток.

## T08. Потоки

Ребро с ёмкостью 5 пропускает до 5 единиц. Во все промежуточные
вершины столько же единиц входит, сколько выходит. Максимальный
поток отвечает, сколько всего можно отправить из истока `s` в сток `t`.

**Как собрать сеть.** Для распределения задач добавляем дуги `s→люди`
с лимитом задач на человека. Дуги `люди→задачи` для допустимых
назначений и `задачи→t` имеют ёмкость 1. Если отдел может взять всего 10 задач,
ставим между `s` и людьми отдела общий узел с входящей ёмкостью 10.
Так индивидуальные и общий лимиты соблюдаются одновременно.

Обратная остаточная дуга позволяет отменить часть прошлого назначения.
Когда из `s` уже нельзя дойти до `t` по остаточным дугам, поток максимален.
Вершины, достижимые из `s`, образуют одну сторону минимального разреза.

Если у назначений есть цена, ставим её на соответствующие дуги и
используем поток минимальной стоимости. Для ровно `K` назначений
вызываем `solve(s,t,K)`. Если полученный поток меньше `K`, столько
назначений сделать невозможно.

## T09. Деревья, LCA и HLD

- Поддерево занимает отрезок `[tin[v],tout[v])`, если нумеровать
  вершины по входу в DFS. Запрос к поддереву становится запросом к массиву.
- Для `p=lca(u,v)` расстояние равно `depth[u]+depth[v]-2·depth[p]`.
  Для взвешенного дерева вместо глубины берём сумму весов от корня.
- HLD соединяет вершину с её самым большим ребёнком. Переход в любую
  другую ветку уменьшает размер поддерева хотя бы вдвое. Путь делится
  на `O(log n)` отрезков цепей. На каждом работает дерево отрезков.

## T10. Дерево отрезков и отложенные обновления

Для запроса суммы храним сумму, для максимума — максимум. Ответ
на большом отрезке собираем из ответов его детей. При массовом
`+x` сумма меняется на `x·len`, а максимум на `x`. Прибавку можно
запомнить в вершине и передать детям, когда понадобится спуститься.
Для разных операций заранее решите, как объединять их в одном теге.

## T13. Математическое ожидание

Среднее число событий равно сумме их вероятностей, даже если они
зависят друг от друга. Например, в случайной перестановке каждая пара
образует инверсию с вероятностью `1/2`, значит, в среднем их `n(n-1)/4`.

Для числа шагов до успеха можно начать с первого шага. Если бросаем
кубик до шестёрки, среднее число бросков `E=1+(5/6)E`, откуда `E=6`.

## T14. Комбинаторика

**Что считать — порядок или набор?** `n! = 1·2·…·n`, `0! = 1`.

- **Перестановки `P(n)=n!`.** Расставить все `n` разных объектов.
- **Размещения `A(n,k)=n!/(n-k)!`.** Выбрать `k` разных объектов
  и упорядочить их. Из 5 участников выбрать первое и второе место
  можно `5·4=20` способами.
- **Сочетания `C(n,k)=n!/(k!(n-k)!)`.** Выбрать `k` объектов в группу.
  Из 5 выбрать команду из двух можно `20/2=10` способами. Если
  `k<0` или `k>n`, полагаем `C(n,k)=0`.
- **Повторы разрешены.** Для `k` позиций с `n` вариантами в каждой
  есть `n^k` последовательностей. Для неупорядоченного набора с
  повторениями есть `C(n+k-1,k)` вариантов при `n≥1`.

Если некоторые элементы уже одинаковые и нужно расставить все, делим
`n!` на факториалы их частот. Например, из `A,A,B,C` получается
`4!/2!=12` разных строк.

**Шарики и перегородки.** Раздаём `S` одинаковых шариков по `k`
разным коробкам. В строке из `S` шариков и `k-1` перегородок число
шариков между перегородками задаёт содержимое коробки. Если пустые
коробки допустимы, ответ `C(S+k-1,k-1)`. Если каждой нужно хотя бы
по одному, сначала раздаём `k` шариков и считаем остаток. Ответ
`C(S-1,k-1)` при `S≥k`, иначе 0.

Например, 4 шарика в 3 коробки можно разложить `C(6,2)=15` способами.
Если в каждой должно быть максимум 2, вычитаем случаи, где какой-то
коробке досталось хотя бы 3. Для каждой из трёх коробок заранее
кладём туда 3 и распределяем последний шарик тремя способами.
Два нарушения одновременно невозможны. Остаётся `15-3·3=6`.
При нескольких одновременных нарушениях сначала вычитаем каждое,
затем возвращаем пересечения пар и дальше чередуем знаки.

**Быстрый подсчёт.** Формула Паскаля `C(n,k)=C(n-1,k-1)+C(n-1,k)`
разделяет наборы по тому, взяли ли последний объект. Также
`C(n,k)=C(n,n-k)` и `Σ C(n,k)=2^n` по всем `k` от 0 до `n`.
По простому модулю `p` при `n<p` заранее считаем `fact` и обратные
`invfact`. Тогда `C(n,k)=fact[n]·invfact[k]·invfact[n-k] mod p`.
Начинаем с `invfact[n]=fact[n]^(p-2) mod p` и идём вниз по формуле
`invfact[i-1]=i·invfact[i] mod p`.

## T15. Свёртка целых чисел через FFT

Если `a[i]` и `b[j]` — частоты весов в двух группах, число пар
с суммой `k` равно сумме `a[i]·b[j]` по всем `i+j=k`.
Например, `[2,1]` и `[3,4]` дают `[6,11,4]`. Для суммы 1 получается
`2·4+1·3=11`. Это коэффициенты произведения `(2+x)(3+4x)`.

FFT вычисляет значения обоих многочленов в одних и тех же точках.
Их можно перемножить поэлементно, затем обратная FFT восстанавливает
коэффициенты. `convolution_fft(a,b)` делает всё за `O(N log N)`.
`N` — ближайшая степень двойки не меньше `a.size()+b.size()-1`.
Для разностей переворачиваем `b` и читаем разность `d` по индексу
`d+b.size()-1`. Заготовка использует округление. Её пределы —
`N≤2^20` и произведение норм входных массивов не больше `10^12`,
где норма — корень из суммы квадратов.

## T17. Строки

- `pi[i]` — длина самого длинного собственного префикса `s[0..i]`,
  который одновременно его суффикс. Следующую меньшую границу берём
  через `pi[j-1]`. Это переходы KMP.
- Z-функция отвечает, сколько символов с позиции `i` совпадает
  с началом строки. Для многих шаблонов используем Ахо–Корасик.
- Число различных подстрок через суффиксный массив равно
  `n(n+1)/2-ΣLCP`. Манакер находит радиусы палиндромов за `O(n)`.

## T18. Геометрия

`cross(b-a,c-a)` показывает сторону от прямой `a→b`. Плюс означает
слева, минус справа, ноль означает, что точки на одной прямой.
Точка лежит на отрезке, если она на этой прямой и её координаты
в пределах координат концов.

Два отрезка пересекаются, если их прямоугольники по координатам
перекрываются и для каждого отрезка концы другого лежат по разные
стороны его прямой или на ней. Проверяем знаки `cross`.

Чтобы спроецировать `p` на прямую через `a` с направлением `d`, берём
`h=a+d·dot(p-a,d)/dot(d,d)`. Отражение — `2h-p`. Для целых координат
сравниваем квадраты расстояний. Удвоенная площадь простого многоугольника
равна `|Σ cross(p[i],p[i+1])|`, последнюю вершину соединяем с первой.

## T20. Игры, Ним и числа Гранди

Эти правила подходят, если оба игрока имеют одинаковые допустимые ходы
из каждого положения, игра обязательно заканчивается и игрок без хода
проигрывает.

**Ним.** За ход можно убрать любое положительное число камней из одной
кучи. Считаем XOR размеров всех куч. Если он равен 0, при правильной
игре победит соперник. Иначе ищем кучу размера `h`, для которой
`h xor S < h`, где `S` — общий XOR. Уменьшаем её до `h xor S`.
Например, у куч `2,3,4` общий XOR равен 5. Заменяем 4 на `4 xor 5=1`
и оставляем сопернику XOR 0.

**Гранди.** Для положения без ходов `g=0`. В остальных положениях
берём `g=mex` чисел всех положений, куда можно сходить за один ход.
`mex` — наименьшее отсутствующее неотрицательное число, например
`mex({0,2})=1`. Если игра распадается на независимые части и каждый
ход меняет ровно одну часть, XOR их чисел Гранди работает как в Ниме.

## T24. Делители по факторизации

Для `n=∏p[i]^a[i]` количество делителей равно `∏(a[i]+1)`, а сумма
равна `∏(1+p[i]+…+p[i]^a[i])`. Например, для `12=2²·3` получаем
6 делителей с суммой `(1+2+4)(1+3)=28`. Степень простого `p` в `n!`
равна `floor(n/p)+floor(n/p²)+…`.
