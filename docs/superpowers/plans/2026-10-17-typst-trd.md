# Typst TRD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** `make typst` создаёт `build/trd.pdf` в одну колонку из выбранных YAML фрагментов C++.

**Architecture:** Корневой `trd.typ` читает `trd.yaml`, извлекает отмеченный код
из перечисленных файлов и оформляет документ. Makefile вызывает Typst напрямую,
независимо от настройки CMake.

**Tech Stack:** Typst CLI и его стандартная библиотека, YAML, Make.

**Spec:** `docs/superpowers/specs/2026-10-17-typst-trd-design.md`.

## Global Constraints

- A4, одна колонка, PDF в `build/trd.pdf`.
- Единственная новая зависимость сборки документа — Typst CLI.
- Python, YAML-библиотеки и внешние пакеты Typst не нужны.
- Обычный `make` не требует Typst и не запускает сборку документа.
- Постоянную инфраструктуру тестов в репозиторий не возвращать.
- Метки занимают отдельные строки; сохранять отступы кода, поддерживать LF и CRLF.

## Review Focus

- Специальные символы C++ и кириллица выводятся буквально, без интерпретации разметки.
- Несколько фрагментов объединяются с пустой строкой; пробелы вокруг меток допустимы.
- Пустые, вложенные, отсутствующие и несбалансированные метки дают ошибку с путём файла.
- Файлы вне YAML не читаются; порядок YAML сохраняется после его изменения.
- Длинные строки и переходы страниц не обрезают код; шрифты доступны без скачивания.

## Files

- Create `trd.typ`: извлечение, проверка YAML и оформление.
- Create `trd.yaml`: начальный состав всех пяти реализаций.
- Modify `Makefile`, `README.md`: команда сборки и документация.
- Modify пять `.hpp` в `include/algo/`: только добавить метки вокруг включаемого кода.

### Task 1: Шаблон и конфигурация

**Interfaces:** `trd.yaml` содержит непустой `title` и массив `sections`;
каждый раздел содержит `title` и массив `files`, каждый файл — `title` и `path`.
`extract-code(source, path)` в `trd.typ` принимает две строки, возвращает строку
с извлечёнными фрагментами либо завершает сборку диагностикой с `path`.

- [x] Проверить доступность Typst CLI; при отсутствии установить его с необходимым
  разрешением. Проверить официальную документацию используемых функций.
- [x] Во временной директории подготовить минимальный YAML и C++ с LF/CRLF,
  двумя фрагментами, отступами, кириллицей и символами `#`, `$`, обратными кавычками.
  До реализации вызов компилятора с отсутствующим `trd.typ` должен завершаться ошибкой.
- [x] Создать `trd.typ`: проверять типы/поля конфигурации; обходить разделы и файлы
  в порядке YAML; разбирать код построчно конечным автоматом вне/внутри фрагмента.
  Начало и конец распознавать по точной строке после удаления внешних пробелов.
  Отвергать пустые фрагменты и нарушения последовательности с путём файла.
- [x] Добавить оформление: встроенные шрифты с кириллицей, A4, одна колонка,
  оглавление, номера страниц, нумерованные заголовки, `raw(lang: "cpp", block: true)`
  и разрешённые разрывы блока кода между страницами.
- [x] Создать `trd.yaml` с разделами «Структуры данных» и «Строковые алгоритмы».
  Добавить метки в пять заголовков; у Ахо — Корасика исключить комментированный пример.
- [x] На временных конфигурациях проверить успешное извлечение и каждый вид ошибки:
  нет меток, лишний END, вложенный BEGIN, незакрытый BEGIN, пустой фрагмент,
  отсутствующий файл, неправильный YAML и неправильные типы полей.
  Для положительных примеров сверить извлечённый текст PDF: код сохранён, метки и
  содержимое вне фрагментов отсутствуют. Повреждённый файл вне YAML не влияет на сборку.

### Task 2: Команда сборки и проверка документа

**Interfaces:** `make typst` компилирует корневой `trd.typ` в `build/trd.pdf`;
цель phony, каждый вызов учитывает актуальные YAML и исходники. `make clean`
использует существующее удаление `build/`.

- [x] До добавления цели проверить, что `make -n typst` сообщает об отсутствии цели.
- [x] Добавить phony-цель `typst`, создающую `build/` и вызывающую `typst compile`.
  При отсутствии CLI вывести понятную подсказку; не запускать CMake для этой цели.
- [x] Обновить README: зависимость Typst, `make typst`, путь PDF, схема YAML,
  относительность путей, порядок, несколько фрагментов и ошибки меток.
- [x] Выполнить `make typst`; извлечь текст PDF и отрендерить страницы в PNG.
  Визуально проверить все страницы: кириллицу, оглавление, нумерацию, читаемость,
  длинные строки и переносы. Временные инструменты проверки не добавлять в репозиторий.
- [x] На временной копии поменять порядок YAML и содержимое исходника;
  повторный `make typst` должен отразить изменения. Проверить `make clean` и сборку
  после очистки, обычный `make`, `git diff --check` и отсутствие изменений алгоритмов
  помимо добавленных меток.
