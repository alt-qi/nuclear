## 2016 D. Demolition Time: две цепочки границ

**Что надо считать.** Различаются наборы исходных позиций, а не одинаковые строки.
Сначала обычным KMP считаем вхождения до первого удаления. Каждое новое вхождение
появляется ровно при удалении последнего здания внутри его разрыва.

Пусть сейчас удаляется позиция `x`, длина образца равна `m`. Слева от `x` уже
остались только здания, которых вообще нет в плане сноса: удаления идут слева
направо. Справа пока стоит исходный суффикс. Новое вхождение состоит из `j`
оставшихся зданий слева и `m-j` зданий справа, где `1 <= j < m`.

Прогоним KMP образца по остающимся слева символам. Пусть его состояние равно
`L`. Допустимые длины `j` — предки `L` в дереве префикс-функции. В обратном
направлении KMP перевёрнутого образца по исходной строке даёт состояние `R`
для суффикса после `x`. Нужно посчитать разбиения, где `m-j` — предок `R`.

Для каждого `j` заведём прямоугольник: поддерево вершины `j` первого дерева
на поддерево `m-j` второго. После нумерации Euler это прямоугольники на сетке.
Запрос удаления — точка `(tin[L], tin[R])`; ответ — число покрывающих её
прямоугольников. Решаем все запросы офлайн: события начала/конца прямоугольника
по первой координате, range-add / point-query Fenwick по второй.

**Почему нет повторов.** Один набор становится соседним после последнего
удаления внутри его крайних позиций. Позже он либо сохраняется, либо теряет
выбранное здание. Повторно появиться он не может.

Время `O((|s|+m) log m)`, память `O(|s|+m)`, ответ хранить в `int64`.
При `m=1` новых вхождений после удаления нет.
Проверено 15 000 малых примеров сравнением с явным множеством наборов позиций
во все моменты сноса.

## 2018 B. Balanced Advertising: поток с отрицательными рёбрами

Поставим каждому исходному ребру метку `-1`, `0` или `1`. Суммы меток около
каждой вершины должны лежать в `[-1,1]`; максимизируется сумма всех меток.

Строим сеть: `s -> пользователь` ёмкости 1, `сайт -> t` ёмкости 1, а для каждой
пары добавляем две противоположные дуги ёмкости 1. Целочисленный максимальный
поток задаёт метку как поток слева направо минус поток справа налево. Встречные
единицы сокращаются. По меткам восстанавливаем две компании.

**Почему разрешено потребовать неотрицательный баланс.** Рассмотрим любое
решение как ориентированные единичные рёбра: положительные направлены слева
направо, отрицательные — обратно. Разложим его на пути и циклы. Путь из левой
доли в правую даёт вклад `+1`, обратный — `-1`, путь внутри одной доли и цикл —
0. Оставив только первые пути, не уменьшаем цель и получаем балансы 0 или 1
на обеих долях. Именно такие решения описывает построенная сеть.

Все дуги единичные. Для Диница применима оценка
`O(E min(V^(2/3), sqrt(E)))` для сетей с единичными ёмкостями; это не общая
задача на плотную матрицу стоимостей. Обычное максимальное паросочетание
исходного графа описывает меньше решений и может дать неверный оптимум.
На 600 малых двудольных графах результат совпал с перебором всех меток рёбер.

## 2018 J. Judge Problem: сначала трудные задачи

Проверим, можно ли ограничить нагрузку каждого члена жюри числом `K`.
Сортируем задачи по убыванию сложности. Если автор текущей задачи способен её
сделать и у него осталось место, отдаём задачу ему. Иначе берём любого члена
жюри со свободным местом и общим порогом `a >= d`. Если такого нет — `K` мало.

**Обмен.** Зафиксируем оптимальное назначение, совпадающее с жадным на уже
обработанных задачах. Если выбранный жадно человек занят будущей задачей,
поменяем её с текущей. Прежний исполнитель текущей задачи, если это не автор,
имеет `a >= d`, поэтому справится с любой будущей, более лёгкой задачей.
Если автор недоступен жадному алгоритму, его места уже заняты зафиксированными
задачами: оптимальному продолжению он тоже недоступен. Это доказывает шаг.

Для быстрой проверки сортируем людей по `a` и добавляем их в стек кандидатов
по мере уменьшения `d`. Занятых людей лениво убираем с вершины. Остатки мест
храним отдельно, поэтому назначения автору тоже учитываются. После сортировок
одна проверка линейна. Бинарный поиск `K` даёт `O((n+m) log(n+m))` времени.
Отдельно проверить `K=n`: если и это не помогает, ответ `-1`.
20 000 случайных малых тестов совпали с полным перебором назначений.

## 2018 K. Kingdom and Reforms: чередование эйлерова обхода

У каждой вершины должны встретиться оба цвета рёбер. Степень считает петлю
дважды. Вершина степени 0 или 1 сразу делает ответ невозможным.

В компоненте с нечётными степенями добавим временную вершину и соединим её
со всеми вершинами нечётной степени. Найдём эйлеров цикл, начиная во временной
вершине, и покрасим его рёбра попеременно. Затем удалим временные рёбра.
Каждая настоящая нечётная вершина имела степень хотя бы 3; удаление одного
временного ребра сохраняет у неё оба цвета.

Если все степени чётные, при чётном числе рёбер обычного чередования хватает.
При нечётном начнём цикл в вершине степени хотя бы 4. Только на стыке первого
и последнего ребра возможен одинаковый цвет; у стартовой вершины есть ещё
другая пара прохода, которая содержит оба цвета. Если такой вершины нет,
компонента является нечётным циклом, включая одиночную петлю, и решения нет.

Алгоритм Хиерхольцера даёт `O(n+m)`. Хранить идентификаторы рёбер: это важно
для петель и кратных дорог. Проверено 10 000 мультиграфов против полного
перебора двух цветов.

## 2019 F. Toll Road: состояние определяется непомеченными точками

Рассмотрим блок между соседними дорожными воротами. В нём можно оставить без
ворот не больше одного въезда и не больше одного выезда. Иначе два въезда
нельзя различить по поездкам к последнему выезду; аналогично для выездов.
Если непомечены и въезд, и выезд, выезд должен стоять раньше въезда: иначе
поездка между ними вообще не встретит ворот.

Эти условия и достаточны. Для двух одинаковых наборов наблюдений помеченные
концы совпадают по собственным воротам. Непомеченные концы должны лежать в
одном блоке, где каждого типа не больше одного. Поездок без наблюдений условия
тоже не допускают.

Сканируем точки по координате. В DP четыре состояния непомеченных концов
текущего блока: пусто, `E`, `T`, `TE`. Точку можно пометить за `a`, не меняя
состояние; оставить непомеченной, если новое состояние допустимо; перед ней
можно поставить дорожные ворота за `b` и сбросить состояние. Переход `T -> TE`
разрешён, `E -> ET` запрещён. Сортировка и затем `O(n)` переходов, `O(1)`
рабочей памяти. Координатный зазор всегда позволяет поставить полувещественные
ворота. Ответ — `int64`.
252 малых случая совпали с перебором всех наборов ворот.

## 2019 H. Rebellious Sequences: достаточно двух подпоследовательностей

Пусть `N=n/2`, `L` — длина начальной серии открывающих скобок, `R` — длина
конечной серии закрывающих. Ответ:

$$L+R\le N-2.$$

**Необходимость для любого числа частей.** В каждой непослушной части до её
последней открывающей должна встретиться хотя бы одна лишняя закрывающая.
Если в часть попало `l` скобок из начальной серии, ей нужно хотя бы `l+1`
закрывающих вне конечной серии. Для `k >= 2` частей суммируем:
`N-R >= L+k`, откуда условие.

**Достаточность.** Пусть `t` — первая закрывающая, `u` — `(L+2)`-я закрывающая.
Условие говорит, что после `u` ещё есть открывающая. Построим часть A: возьмём
закрывающую в `t`, затем `balance(u)+2` открывающих между `t` и `u`, затем
`balance(u)+1` закрывающих после `u`. Все они существуют. В A баланс сначала
отрицателен, а в `u` равен `balance(u)+1`. Поэтому у оставшейся части B баланс
в `u` равен `-1`. Обе части заканчиваются балансом 0 и обе непослушны.

После обменов поддерживаем множества позиций открывающих и закрывающих.
Первая закрывающая задаёт `L`, последняя открывающая — `R`. Запрос `O(log n)`.
Критерий проверен на всех 64 правильных последовательностях длины до 10:
перебирались разбиения на произвольное число непослушных подпоследовательностей.

## 2020 F. Fun at Luggage Claim: кто может срабатывать

Ключевая лемма: две соседние клетки не могут обе сработать. После получения
чемодана от соседа клетка выше этого соседа не больше чем на 1, поэтому не
может сработать. Следующее получение снова оставляет такой блокирующий сосед;
рост соседей от других клеток тоже не помогает. Следовательно, все срабатывающие
клетки образуют независимое множество и сами ничего не получают.

Значит для `a[i] > b[i]` число операций обязано быть
`k[i]=(a[i]-b[i])/2`; для остальных `k[i]=0`. Проверяем целочисленность,
отсутствие соседних положительных `k` и все уравнения

$$b_i=a_i-2k_i+k_{i-1}+k_{i+1}.$$

Осталось проверить допустимость порядка. Выполним все операции доноров по
возрастанию их конечной высоты `b[i]`, каждый блок подряд. У клетки-получателя
не больше двух доноров. Пусть до блока донора `i` у неё `h` чемоданов. Для
последней операции нужно и достаточно `h+k[i]-1 <= b[i]`. После проверки
увеличиваем `h` на `k[i]`.

**Почему этот порядок полный.** Последний из двух доноров должен выдержать
итоговую высоту получателя минус 1. Если это выдерживает меньший донор,
выдерживает и больший; более ранняя работа меньшего только ослабляет его
ограничение. Если меньший не выдерживает итог, он обязан закончить раньше
большего. Поэтому ограничения порядка всегда согласованы с возрастанием `b`.
Проверку можно делать локально у каждого получателя, без сортировки: `O(n)`.
70 914 распределений совпали с полным графом разрешённых операций.

## 2020 M. Matrix 4: чётный алгоритм Евклида

Это дополнительный материал, а не обязательная теория для команды.
Для матрицы `(p,q;r,s)` критерий:

$$ps-qr=1,\quad q\equiv r\equiv0\pmod2,\quad
p\equiv s\equiv1\pmod4.$$

Необходимость следует из четырёх операций над столбцами. Для достаточности
сокращаем верхнюю строку: из большего по модулю числа вычитаем ближайшее
**чётное** кратное меньшего, применяя ту же операцию ко всему столбцу.
Нечётное `p` и чётное `q` по модулю не равны; новый остаток строго меньше
делителя. Получим `q=0`, затем по определителю `p=s=1` или `-1`.
Остаток по 4 исключает `-1`. Остаётся убрать чётное `r`.

Все сокращения — обратные разрешённые ходы. Ответ получается обращением их
порядка и знаков; большие кратности записываем повторяющимися группами.
Здесь нельзя округлять отношение к чётному кратному с помощью усечения C++
к нулю: нужен именно ближайший остаток, с обработкой отрицательных чисел.

За два сокращения максимальный модуль верхних чисел уменьшается хотя бы вдвое.
Вторая строка тоже остаётся малой: например, при сокращении первого столбца
`r'=(p's-1)/q`, а `|p'|<|q|`, откуда `|r'| <= |s|+1`.
Поэтому при входной границе `10^6` ограничение промежуточных координат `10^9`
имеет большой запас. Длина сжатого маршрута логарифмическая и укладывается
в 1024 байта. 10 000 матриц, полученных разрешёнными ходами, сократились к I.

## 2020 N. New Randomized Go: плохие полуокружности

Точки одного цвета не охватывают центр тогда и только тогда, когда все они
помещаются в открытую полуокружность. Пустое множество тоже плохое. Для
непустого плохого множества есть единственный якорь: точка сразу после зазора
длины строго больше половины окружности.

Отсортируем точки, удвоим цикл: `x[i+n]=x[i]+l`. Пусть `r[i]` — последняя
точка, для которой `2(x[r[i]]-x[i]) < l`. Два указателя находят все `r`.
Число раскрасок с плохим красным цветом:

$$B=1+\sum_{i=0}^{n-1}2^{r_i-i}.$$

Для пересечения двух плохих событий рассмотрим два разных якоря `i,j`.
Если `i<j<=r[i]`, полуокружности покрывают все точки тогда и только тогда,
когда `r[j] >= i+n-1`. Их общие точки, кроме синего якоря `j`, свободно
красятся: получается `2^(r[i]-j)` раскрасок. Удвоим сумму, чтобы учесть оба
порядка цветов. Для диаметрально противоположных якорей есть одна раскраска
на каждую упорядоченную пару. Ещё две раскраски с пустым цветом подходят,
если все точки лежат в одной открытой полуокружности.

Таким образом, если `S` — указанная сумма по `i,j`, `D` — число упорядоченных
диаметральных пар, `A` — индикатор общей полуокружности, то

$$W=2^n-2B+2S+D+2A.$$

Для фиксированного `i` допустимые `j` образуют суффикс `[lo,r[i]]`, поскольку
`r[j]` не убывает. Сумма равна `2^r[i]` на сумму `2^(-j)` этого отрезка:
префиксные суммы обратных степеней дают `O(1)`. Все границы сдвигаются двумя
указателями. Сортировка `O(n log n)`, дальше `O(n)`. Ответ `W/2^n` по модулю.
Открытая граница обязательна: диаметральная пара уже содержит центр.
Проверено 4004 набора точек против всех их раскрасок.

## 2021 C. Socks Drying: считать пары цветов

У каждого цвета в куче непарных носков бывает ровно 0 или 1 носок: это
чётность числа уже вынутых носков данного цвета. Извлечения занимают
`2 sum(a[i])` секунд. Ещё `sum(a[i])` сравнений приходится на сами найденные
пары. Всё остальное можно посчитать по неупорядоченным парам цветов.

Рассмотрим два цвета с `a,b <= 5` парами. В относительном случайном порядке
их `2a+2b` носков состояние — `(u,v)`, сколько носков каждого цвета уже вынуто.
Следующий носок первого цвета имеет вероятность `(2a-u)/(2a+2b-u-v)`.
Если `v` нечётно, носок второго цвета лежит в куче и будет рассмотрен:

- с вероятностью 1, когда `u` чётно: пары первому цвету в куче нет;
- с вероятностью `1/2`, когда `u` нечётно: подходящий носок первого цвета и
  носок второго цвета равновероятно идут первым в случайном порядке проверки.

Для второго цвета симметрично. DP на сетке до `11 x 11` даёт вклад `F[a][b]`.
Считаем частоты пяти значений `a[i]`. Разные группы дают
`count[a] count[b] F[a][b]`, одна группа — `C(count[a],2) F[a][a]`.
Добавляем базовые `3 sum(a[i])` секунд. Время `O(n+25*121)`, память `O(1)`.
Независимость цветов не нужна: линейность ожидания работает и без неё.
Проверены все относительные порядки для кратностей 1–3 и все четыре примера.

## 2021 D. Christmas Children Circle: чинить только стык

Решение существует всегда для непустых мешков. Пройдём детей по порядку:
если входящее число есть в текущем мешке, передаём именно его; иначе выбираем
любое своё число. Все переходы, кроме последнего к первому, уже корректны.

Пусть последний ребёнок передаёт `v`. Если его нет в первом мешке, всё готово.
Иначе заменяем ответы на `v` в начальной непрерывной цепочке мешков, где оно
есть. Внутри цепочки вход и выход одинаковы. На её конце следующий мешок
не содержит `v`, поэтому прежний ответ там допустим. Стык последнего и первого
теперь тоже исправлен. Если цепочка охватила весь круг, все передают `v`.

Отсортированные мешки дают `O(S log S)` времени и `O(S)` памяти; с хешами —
ожидаемое `O(S)`. Двух проходов достаточно, пробовать все стартовые числа не надо.
Полный перебор 137 249 кругов с числами 0–2 подтвердил конструкцию.

## 2021 E. Construct The Integer: НОД анаграмм и BFS чисел

Если все цифры одинаковы, анаграмма одна и её НОД — само число. Поэтому любое
положительное число из одинаковых цифр является минимальным ответом для себя.

Иначе пусть `g` — НОД разностей различных цифр. Тогда

$$G(z)=\gcd(z,9g),\qquad 1\le g\le9.$$

Любая перестановка получается обменами цифр. Разность двух порядков кратна
`9g`, поэтому `gcd(z,9g)` делит все анаграммы. Обратно: любые две разные цифры
можно поставить в два последних разряда. Разность этих анаграмм равна
`9(d-e)`. Значит общий НОД делит `9g` и `z`. Ведущие нули разрешено отбрасывать,
поэтому это доказательство не требует исключать перестановки с нулями.

Отсюда для `n>81` ответ существует только в случае одинаковых цифр самого `n`.
Для `n<=9` ответ равен `n`. Остальное можно предвычислить один раз:
перебираем множества цифр с `g>=2`; для каждого BFS в состоянии
`(маска уже использованных цифр, остаток по 9g)`. Начальный ноль запрещён,
следующие цифры перебираются по возрастанию. BFS находит минимальное число
для каждого состояния. В состоянии полной маски записываем кандидата для
`gcd(остаток,9g)`; сравниваем по длине, затем лексикографически.

В одном таком множестве не больше пяти цифр: все они одинаковы по модулю `g`.
Значит конечный автомат мал. Множества с `g=1` дают только ответы 1,3,9,
которые уже оптимальны. Дополнительно учитываем числа из одинаковых цифр.
Нетривиальные минимумы:

| n | z | n | z |
|---|---|---|---|
| 12 | 48 | 15 | 5055 |
| 18 | 288 | 21 | 7077 |
| 24 | 8088 | 27 | 3699 |
| 36 | 48888 | 45 | 5055555555 |
| 54 | 222888888 | 63 | 111888 |
| 72 | 8088888888 | 81 | 9099999999 |

Например, для `n=22` ответ всё равно 22: это случай одинаковых цифр.
Для остальных `n` ответа нет. Формула НОД проверена перебором анаграмм чисел
до 300; минимумы совпали с прямым перебором чисел до 100 000.

## 2023 A. Anxious About Airdrops: ближайший к одному игроку

Не нужно каждый раз искать глобально ближайшую пару. Берём любую занятую
точку `p` и ближайшую к ней другую занятую точку `q` на расстоянии Манхэттена
`d`. Ставим аирдроп в целую точку кратчайшего пути так, чтобы расстояние от
`p` было `floor(d/2)`, а от `q` — `ceil(d/2)`.

Для любого другого игрока `r` расстояние до `p` не меньше `d`. По неравенству
треугольника его расстояние до аирдропа не меньше `ceil(d/2)`. Поэтому первый
достигает аирдропа через `floor(d/2)` секунд, а за дополнительную секунду
решения туда гарантированно успевает `q`. Число занятых точек уменьшается.

За одну итерацию находим ближайшего к `p`, затем явно двигаем всех игроков
по правилу «сначала горизонтально». Объединяем совпавшие точки. Всего не больше
`n-1` итераций по `O(n)`, то есть `O(n^2)`, память `O(n)`. Аирдроп внутри
прямоугольника двух исходных точек, поэтому границы координат соблюдаются.

## 2019 B. Почему допустим переход от решётки к симплексу

После урны Пóльи положительные целые композиции общего капитала `T` равновероятны.
Условие минимума `m` превращает их в неотрицательные композиции `R=T-nm`
с хотя бы одним нулём. В непрерывном пределе выбираем нулевую координату,
а остальные `n-1` координат равномерны на симплексе массы `1-na`.
Ожидание наибольшей координаты равномерного симплекса размерности `d-1`
равно `H[d]/d`. Поэтому ответ:

$$a+(1-na)\frac{H_{n-1}}{n-1}.$$

Здесь приближение можно обосновать, а не только сослаться на огромный `T`.
Равномерная композиция в `d` частей — случайные разделители среди
`R+d-1` позиций. Сопоставим их с округлёнными непрерывными случайными
разделителями: вероятность совпадений `O(d^2/R)`, ошибка нормированных длин
`O(d/R)`. Смесь граней отличается от равномерной поверхности только весом
точек с несколькими нулями; их вероятность `O(n^3/R)`. После умножения
на массу `R/T` абсолютная ошибка имеет порядок `n^3/T`.
При `T=2020^2019`, `n<=2000` это несравнимо меньше `10^-6`.
При `R=0` ответ ровно `a`; деление на `R` в программе не требуется.
